# 미션16 재검토

**판단: 한계를 함께 설명하면 탐색적 분석 포트폴리오로 공개할 수 있다.** 입소문이나 프로모션의 효과를 입증한 프로젝트로 소개하기에는 자료가 부족하다. 이번 검토는 저장된 제출본을 대상으로 했으며, 외부 원자료까지 확인한 완전한 검증은 아니다.

관측 기간은 2026-09-23~2026-10-06으로 유지했다. 일별 CSV에서 전일·전주 170쌍의 관객·스크린·상영횟수·회당 관객 변화율과 순위 변화를 직접 다시 계산했다. 후보 설정 48개와 파일 해시 32개도 확인했다. 관객·순위 시계열과 개봉 후 등장일수 그림을 새로 확인했으며, 나머지 그림은 기존 검증 기록과 코드를 참고했다. 전체 노트북 재실행, API 일별 원응답 재조회, 기사·기관 원자료의 최신 재검증은 이번 범위에 포함하지 않았다.

## 우선 보완할 내용

### 1. 기준을 사전에 정했다는 설명은 수정해야 한다

노트북 10단계의 ‘사전에 함께 비교하는 탐색 기준’은 실제 작업 순서와 맞지 않는다. 후보 기준별 비교는 첫 결과를 본 뒤 추가했다. 미리 정한 기준과 결과를 본 뒤 확장한 기준은 연구자가 행사한 선택의 범위가 다르다.

**수정:** 윤문본에는 ‘첫 결과를 확인한 뒤 추가한 탐색 기준이며, 사전 등록한 분석은 아닙니다’라고 적었다. README와 분석 결정 기록에서도 같은 작업 순서를 설명했다. 계산 결과는 바꾸지 않았다.

### 2. ‘공휴일 효과를 제거했다’고 소개하면 안 된다

개봉 후 비교 50건에서 공휴일 여부가 같은 28건을 남겼다. 남은 날짜는 9/30·10/3·10/4·10/6 각 7건이다. 이 중 10/3의 7건은 개천절과 9/26 추석 연휴를 비교한다. 공휴일이라는 구분은 같아도 휴일의 성격과 관객 행동이 같다고 볼 수 없다.

**보완:** ‘공휴일 여부가 다른 비교를 제외한 결과’라는 표현을 유지한다. 28건 중 다른 종류의 공휴일을 비교한 7건이 있다는 점을 README에 추가했다. 후속 분석에서는 공휴일 종류·연휴 위치·개봉 후 경과일까지 고려해야 한다.

### 3. 후보 없음은 관객 행동의 부재가 아니다

연속 2일 조건에서 엄격한 후보가 없는 것은 이번 자료와 판정 규칙의 결과다. 공휴일 조건으로 날짜를 제외하면 관측의 연속성이 끊기기도 한다. 관객 추천이나 실제 관람 동기는 측정하지 않았다.

**보완:** ‘지속적인 역주행이 없다’보다 ‘이번 14일의 비교 가능한 관측에서는 해당 조건을 충족하지 않았다’고 설명한다. 48개 설정은 기준에 따라 결과가 달라지는지 살펴본 표이지, 독립적인 48회 검증이나 통계적 유의성 검정이 아니다.

### 4. 회당 관객은 관객의 만족도나 자발성을 나타내지 않는다

회당 관객이 늘어난 이유에는 상영관 좌석 수, 시간대, 극장 구성, 단체관람 등이 있을 수 있다. 실제 좌석 수가 없으므로 회당 관객 개선을 좌석점유율이나 입소문의 증가로 읽으면 안 된다. 관객수와 상영횟수의 곱셈 관계는 구성의 설명이며 원인의 분리가 아니다.

**보완:** 포트폴리오에서는 ‘회당 관객 개선’이라는 측정값을 먼저 쓴다. ‘관객 동원력’이나 ‘흥행 효율’은 무엇을 나눈 지표인지 바로 옆에서 설명한다. 전문가 별점도 평가자가 1명인 영화와 11명인 영화가 있어 동일한 정밀도의 평가로 비교하기 어렵다. 상관관계나 장르 효과를 확인했다고 주장하지 않는다.

### 5. 특정 영화의 외부 사건 조사가 비교의 균형을 보장하지 않는다

암살자(들)은 여러 사건을 검토했지만 다른 영화는 같은 깊이의 자료가 없다. 사건 미확인을 ‘프로모션 없음’으로 해석하면 특정 영화의 특수성을 과장할 수 있다. 실제 관람권 사용량과 전국 규모도 확인되지 않았다.

**보완:** README의 중심을 정치적 논란보다 측정·비교의 문제에 둔다. 외부 자료는 왜 인과 해석을 멈췄는지 설명하는 근거로 쓰고, 특정 진영의 목적이나 활동 효과를 분석 결과로 제시하지 않는다. 모든 영화의 동등한 조사와 실제 사용 자료는 후속 과제로 남긴다.

### 6. 재현 가능성과 원자료 검증을 구분해야 한다

저장된 CSV가 노트북에 압축 문자열로 포함돼 있어 같은 입력으로 계산을 다시 수행할 수 있다. 그러나 원래 API 응답과 HTML이 없으므로 그 입력의 출처를 소급해 독립 검증할 수는 없다. 초보자가 긴 압축 문자열에서 자료의 구조를 확인하기도 어렵다.

**보완:** README에 자료 미리보기·데이터 사전·파일 해시와 수집 시점을 연결한다. 압축 문자열은 재현을 위한 선택이라고 설명한다. 포트폴리오 코드 정리에서는 수집·전처리·판정을 나눌 수 있으나, 분리된 파일이 실제 실행되는지 확인하기 전에는 완료된 구조로 소개하지 않는다. 당시 수집 원본은 복원한 것처럼 만들지 않는다.

## GitHub에서 강조할 점

이 프로젝트의 강점은 특별한 흥행 원인을 발견했다는 데 있지 않다. 처음의 질문을 데이터에 맞춰 좁히고, 지표와 비교 기준의 허점을 찾아 해석을 수정한 과정이다. ‘왜 전주와 비교했는가’, ‘왜 순위를 별도로 봤는가’, ‘왜 입소문이라는 결론을 내리지 않았는가’를 코드·표와 연결하면 판단 과정을 보여줄 수 있다.

문체 수정에서는 수치·날짜·출처·한계를 유지했다. 윤문 스킬의 세부 규칙 파일이 설치 경로에서 연결되지 않아 스킬의 등급이나 변경률 판정은 수행하지 않았다. 일반적인 한국어 문장 원칙으로 번역투와 긴 명사 나열을 다듬었다.
